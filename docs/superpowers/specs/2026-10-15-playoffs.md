# Postseason design

Add a playable postseason after the existing regular season. The user selected the top 16 league-wide, seeded 1–16. Every series is best of seven. A full bracket, playoff player statistics, every playoff game box score and Finals MVP must be available.

## Format and interaction

Rank by regular-season wins, point differential, then team ID (matching the default standings). The fixed first-round bracket is 1–16, 8–9, 4–13, 5–12, 2–15, 7–10, 3–14, 6–11. Winners advance without reseeding through quarterfinals, semifinals and Finals. Higher original seed hosts games 1, 2, 5 and 7 (2–2–1–1–1). A series ends immediately at four wins. The bracket always displays all 15 series, including future matchups.

After the regular-season reveal, show a separate Playoffs section. Advance the next slate (one game per unfinished series in the active round), the rest of that round, or all remaining playoffs. Teams missing qualification or eliminated remain able to watch the whole bracket. Show the user's seed/status, champion, Finals MVP, series game results, searchable/sortable playoff-only player statistics, per-game/totals, team filtering, and both-team box scores. Finals MVP uses Finals-only impact among championship-team players with minutes played, ties by Pokémon ID. Display Finals PPG/RPG/APG.

## Data and compatibility

Keep regular-season model 3 unchanged. Store an optional, separately versioned `run.playoffs` (model 1), using existing teams and the frozen match engine. Regular-season standings, awards, aggregates and challenge run counters never include playoff games. All 128 qualified players have separate postseason aggregates; Finals aggregates cover the two finalists. Replay summaries on demand for boxes, using the same engine and fixed per-series/game seeds.

Existing model-3 completed saves can begin playoffs immediately; older model-1/2 recaps remain unchanged and need a new league season. Validate saved playoff data with bounded deterministic replay, including partial progression. Invalid playoff extensions recover the valid regular season with a notice and preserve original bytes until explicit replacement. Simulation yields between games, guards duplicate/stale completion, disables reset while busy and saves only complete requested actions.
