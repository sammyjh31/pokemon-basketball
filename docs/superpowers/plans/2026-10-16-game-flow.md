# Game flow implementation plan

Constraints: no extra random draws in flag-absent games. No draws are added to `leagueSchedule`, `localSchedule` or `nextPlayoffFixture`; fixture-level values come from salted hashes. Gameplay never reads optional reporting. Box-score fields are unchanged. The engine keeps a single seeded stream; flagged games may consume draws differently, only behind the flag.

1. Freeze the current seeded replay (e8681b9). Add `gameFlow.ts` with pure helpers: calendar and rest, playoff context, referee crew, arena condition, playoff rotation and back-to-back target transforms, and the timeout policy. Unit-test each.
2. Declare `gameFlowVersion` on `Run` and `LeagueTeam`, `GameFlowFixture` on `LeagueFixture`, and `GameFlowReport` on `LeagueMatch`. Enable it for new solo runs, new leagues and new local leagues. Adopt at franchise and local-career season boundaries. Carry it through persistence, league/franchise validation, local league parsing, archives and the replay call sites.
3. Wire the engine: version guard (requires court rules), `options.flow`, starting energy, target transforms, playoff pace/usage/pressure/home terms, referee scaling, arena condition and setters into ability and energy effects, timeouts with ATO plays, and the report.
4. Build fixture context in season, playoff and local season builders, interactive franchise fixtures and archives, and store it on summaries.
5. Tests: replay hashes unchanged without the flag, deterministic flagged games, mixed-version rejection, lifecycle adoption, full flagged season plus playoffs, archive replay, and save round-trip. Add a balance audit comparing regular season, playoffs, back-to-backs and crews.
6. Show context in box scores and game insights. Update README and LOCAL_HANDOFF. Typecheck, build, focused and full test runs.

Phase 2 (separate version, on court rules v2 from PR #1): zone-defense identity, off-ball cuts and post seals, and heat-check shot selection.
